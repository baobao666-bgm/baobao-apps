# typora0.11.18

> 返回 [README](../README.md)

安装包约 68 MB；提供 64 位与 32 位两种架构（32 位用 `scoop install baobao-apps/typora0.11.18 --arch 32bit` 安装）。因上游 0.11.18 为静态免付费旧版，本包**不参与 CI 自动更新**。

## 内置修复说明

安装时预置注册表 `HKCU\SOFTWARE\Typora` 的 `IDate` 为远期时间并设置对应的拒绝权限，用于消除「This beta version of Typora is expired」过期弹窗。这两项属于本包**有意为之**的修复：0.11.18 是官方最后一个免费版本，缺少任一项都无法正常启动，因此无论 `%APPDATA%\Typora` 是否由本包管理，注册表这一项都会执行。

改动会被完整记录：只登记**实际新增**的拒绝规则及其精确形状（SID / 权限掩码 / 继承标志），同时记录 `IDate` 的**原值类型**（REG_SZ、REG_DWORD、REG_EXPAND_SZ 等）。卸载时只撤销本包新增的规则，并按原类型写回原值；安装前就已存在的同型规则不会被删除。

撤销是**逐条回读核验**的：

- 记录文件（`<persist>\.registry-state.json`）无法读取，或 schema 不是已知版本时，安装与卸载都会**保留该文件并中止**，并给出人工处理命令——宁可停下来，也不依据实时 ACL 猜测"哪些规则是别人加的"。
- 规则没有撤干净 → **中止卸载**，记录文件保留，修好权限后重跑即可。
- 只有 `IDate` 写不回去（通常是被他人设置的拒绝规则挡住）→ 卸载**照常完成**，但会明确打印"未恢复"及记录中的原值，并保留记录文件供重试或手工写回。
- 撤销动作发生在删除 `%APPDATA%\Typora` 联接**之前**，因此中止时应用仍处于完整可用状态。

同时只修改 `%APPDATA%\Typora\profile.data` 中必要字段（关闭「自动检查更新」、跳过当前最新版本）；文件无法解析时保持原样并提示，不做覆盖。

## 数据说明

正常情况下，`%APPDATA%\Typora` 是指向 `<scoop根目录>\persist\typora0.11.18\TyporaData` 的目录联接，C 盘不保存实际数据；普通卸载保留数据，`scoop uninstall -p` 才会删除。通用语义见 [data-and-uninstall.md](data-and-uninstall.md)。

### 该位置已被别的工具建成联接时

若 `%APPDATA%\Typora` 已经是一个**不由本包管理**的联接：

- 联接指向、联接背后的数据、以及 `profile.data` **都不会被改动**（不写穿别人的目录）；
- 因此**更新提示屏蔽不会生效**，数据也不会进入本包 persist；
- 只有消除过期弹窗的注册表修复照常执行（否则这个版本根本无法启动）；
- 希望这种情况下直接让安装失败，请在安装前设置环境变量 `BAOBAO_STRICT_FOREIGN_LINK=1`。
